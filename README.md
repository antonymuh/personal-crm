# Личная CRM

Приложение для ведения контактов людей, которых я знаю лично: кто это, откуда
знакомы, телефон, почта и заметки о договорённостях. Продуктовая идея и критерии
успеха — в `specs/01-продуктовая-идея.md`.

## Стек

- Next.js (App Router) + TypeScript
- React, Tailwind CSS, shadcn/ui
- PostgreSQL (в Docker), Drizzle ORM
- Vitest и Playwright (автотесты), Prettier (формат кода)
- pnpm

Данные читаются и пишутся только на сервере (Server Components + Server Actions).
Браузер к базе не обращается.

## Что нужно заранее

- Node.js 20+
- pnpm
- Docker Desktop (для локального PostgreSQL)

## Запуск

```bash
# 1. Установить зависимости
pnpm install

# 2. Создать .env из примера и вписать в него значения
cp .env.example .env        # Windows PowerShell: Copy-Item .env.example .env
#    В .env придумайте пароль для POSTGRES_PASSWORD и подставьте его же
#    в DATABASE_URL (формат строки подсказан в .env.example)

# 3. Поднять PostgreSQL в Docker
docker compose up -d

# 4. Создать таблицы в базе
pnpm db:push

# 5. (по желанию) наполнить тестовыми данными — 1000 контактов и 5 групп
#    Работает только на пустой базе: если контакты или группы уже есть, команда остановится
pnpm db:seed

# 6. Запустить приложение
pnpm dev
```

Откройте http://localhost:3000

## Как проверить руками

1. Открыли `/` — виден список всех контактов и их количество.
2. Нажали «Добавить контакт», заполнили имя — контакт появился в списке.
3. Нашли контакт через поиск по имени, открыли карточку, дописали заметку —
   заметка сохранилась и видна в карточке.
4. Открыли тот же адрес в другом браузере — те же контакты (данные в базе).
5. Открыли «Изменить» у контакта, выбрали «Частота общения: Раз в месяц»,
   сохранили — в карточке в блоке «Связь» видна частота, «Последнее общение:
   ещё не отмечали» и метка «Пора связаться». В списке контакт стоит наверху
   с той же меткой.
6. В карточке нажали «Пообщались» — «Последнее общение» стало сегодняшним,
   «Следующий раз» — через месяц, метка пропала. В списке контакт вернулся
   на своё место по алфавиту.
7. Дописали заметку — дата последнего общения не изменилась.
8. Поменяли частоту на «Не задана» — метка «Пора связаться» не появляется,
   сколько бы времени ни прошло.
9. В «Добавить контакт» вписали «Новая группа: Теннис» и сохранили — над списком
   появился фильтр «Все» и «Теннис», у контакта метка «Теннис» в списке и в карточке.
10. В «Изменить» у другого контакта отметили «Теннис» и вписали новую группу
    «Семья» — у контакта обе метки.
11. Выбрали фильтр «Теннис» — в списке только его контакты, в адресе
    `?group=…`. Ввели имя в поиск — фильтр сохранился.
12. При выбранной группе нажали «Переименовать» — новое название видно в фильтре,
    в формах и в метках. «Удалить» → «Оставить» — ничего не изменилось;
    «Удалить» → «Удалить» — группы нет, контакты на месте, показан весь список.

## Полезные команды

- `pnpm dev` — запуск в режиме разработки
- `pnpm build && pnpm start` — продакшен-сборка
- `pnpm test` — автотесты (Vitest). Нужен запущенный Docker с базой
  (`docker compose up -d`). Тесты сами создают отдельную базу `personal_crm_test`
  в том же контейнере и работают только с ней — ваши контакты не трогают
- `pnpm test:e2e` — тесты в настоящем браузере (Playwright). Тоже нужен Docker
  с базой. Собирают приложение, запускают его на http://127.0.0.1:3100 с отдельной
  базой `personal_crm_e2e_test` и проходят главный сценарий, группы и «Пора
  связаться». `pnpm dev` на порту 3000 при этом можно не останавливать.
  Перед первым запуском один раз: `pnpm exec playwright install chromium`
- `pnpm format` — привести код к единому формату (Prettier);
  `pnpm format:check` — только проверить
- `pnpm db:push` — применить схему к базе
- `pnpm db:migrate` — применить миграции из `drizzle/` к базе
- `pnpm db:generate` — сгенерировать SQL-миграцию из схемы
- `pnpm db:seed` — заполнить пустую базу тестовыми данными (1000 контактов, 5 групп)
- `pnpm db:seed --reset` — **удалить все контакты, заметки и группы** и заполнить базу заново
- `pnpm db:studio` — веб-интерфейс к базе (Drizzle Studio)
- `docker compose down` — остановить базу (данные сохраняются в volume)

## Проверки на каждый PR (CI)

На каждый pull request GitHub Actions запускает (вкладка **Checks** в PR):

- **Lint, format, types, unit tests** — ESLint, Prettier, TypeScript, Vitest;
- **E2E (Playwright)** — тесты в браузере. Если упали, отчёт со следами
  (trace) — в Actions → нужный запуск → Artifacts → `playwright-report`;
- **Docker image build** — образ собирается так же, как при выкатке, но никуда
  не отправляется;
- **Security audit** — уязвимости в зависимостях.

База в CI своя, одноразовая, внутри запуска. Красный CI — PR не вливаем,
чиним причину.

## Выкатка на сервер

Выкатка автоматическая: любой push в ветку `main` выкатывает новую версию.

Что происходит после push (видно во вкладке **Actions** на GitHub):

1. GitHub Actions собирает Docker-образ приложения и кладёт его в GHCR
   (`ghcr.io/antonymuh/personal-crm`, тег — хеш коммита).
2. Скрипты из папки `deploy/` копируются на сервер в `/opt/crm/prod`.
3. На сервере `deploy.sh`: скачивает образ → применяет миграции базы разовым
   контейнером → запускает новую версию → проверяет `/health`.
   Упали миграции — новая версия не запускается, работает старая.
4. На сервере остаются только текущий и предыдущий образы.

Пока на GitHub не задана переменная `DEPLOY_HOST`, выкатка пропускается —
только собирается образ.

### Настройки на GitHub (Settings → Secrets and variables → Actions)

- Переменные: `DEPLOY_HOST` (IP сервера), `DEPLOY_USER` (пользователь на сервере),
  `APP_URL` (например `https://app.pocketcrm.co`)
- Секреты: `DEPLOY_SSH_KEY` (ключ деплоя), `DEPLOY_KNOWN_HOSTS` (отпечаток сервера)

### .env на сервере

Файл `/opt/crm/prod/.env`, права 600. Какие строки нужны — в `deploy/.env.example`.

### Если выкатка упала

Во вкладке Actions шаг Deploy красный — новая версия не заработала.
Автоматического отката нет. Откатиться на прошлую версию вручную:

```bash
ssh crm
cd /opt/crm/prod && ./deploy.sh "$(cat .previous-tag)"
```

### Изменения схемы базы

Поменяли `src/db/schema.ts` — выполните `pnpm db:generate` и закоммитьте новые
файлы из `drizzle/`. На сервере миграции применятся сами при выкатке.
